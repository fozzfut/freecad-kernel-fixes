026 - OCCT 8.0.1 BRepGraph: дорогое построение графа (TKBRep)

ЧТО
Построение BRepGraph (BRepGraph::Shapes().Add) на детали в 10-20 раз дороже карт TopExp
(плита с 1024 отверстиями: 42-70 мс и 5-6.5 МБ против 4.4 мс и 0.47 МБ у TopExp). Владелец решил: BRepGraph
обязателен, граф держим постоянным на форму - значит, стоимость построения платится на каждой
загрузке/пересчёте. Профиль (C:/dev/occt8-mig/bg-internals/REPORT.txt) показал, куда уходит время:
- упорядочивание рёбер провода через BRepTools_WireExplorer: 12-48 % (на винте 32 % - это
  BRepTools::UVBounds всей грани, пересчитываемые на КАЖДОМ проводе);
- обход псевдонимов исходной формы по каждому использованию подформы: 10-20 %;
- проверка всего графа после каждого Add, которая работает и в release, а результат выбрасывается:
  1-10 %, а при добавлении деталей по одной - O(N^2) (400 коробок: 0.35 -> 1.98 мс на Add);
- хеш-индексы UID/RefUID/исходных форм с начальной ёмкостью 1: ~57 % памяти графа.

ПОЧЕМУ так можно (ответы не меняются)
T1 - провод без ветвлений обходится цепочкой напрямую: в этом случае проводник на каждой вершине
     берёт единственного кандидата и не читает ни грань, ни допуски, ни p-кривые; стартовая вершина
     выбирается ровно как в BRepTools_WireExplorer::Init. Остальные провода идут через проводник,
     но UV-границы грани считаются один раз на грань.
T2 - каждый шаг обхода псевдонимов определяется кортежем (TShape, положения); повтор кортежа -
     пустая операция, пока карта не меняет значение ключа и не вставляет ранее не найденный ключ.
     При первом таком событии обход переходит в стоковый. Порядок вставки ключей тот же.
T3 - UID выдаются подряд по виду, индексы узлов плотные: вместо хеш-карт - столбцы по виду
     (адрес = номер - база), для ключей вне окна - резервная хеш-карта; проверка границы мутации
     перенесена внутрь ассерта (как в EditorView::CommitMutation) - в debug проверяет как раньше.
Обмен с другими DLL не меняется: экспорт TKBRep 1785 = weekly, импорт = weekly; BRepGraph никто
вне TKBRep не включает (ни OCCT, ни FreeCAD 26.3).

ЦИФРЫ (один парный прогон, C:/dev/occt8-mig/bgp/runs)
Add() последовательно: плита -12 %, refine -25 %, hicmos -21 %, Top -30 %, шариковый винт -52 %,
винт с сеткой -43 %, деталь VR6 -30 %, многоугольник 2000 -49 %, лофт -1 %.
400 коробок по одной: всего -45 %, последние 10 % Add -79 % (квадратичность убрана).
Память графа (отдельный процесс): -10..-39 % (плита -34 %).
Идентичность: полный дамп графа (все узлы, ссылки, отношения, ориентации, UID, привязки,
FindNode, Reconstruct в BREP-тексте, правка+Compact+Copy, Clear) побайтно равен стоку на
23 случаях корпуса; сборка-проверка с обоими путями (26 872 провода, 222 Add) - 0 расхождений;
три мутанта (по одному на улучшение) пойманы 9/9; прогон FreeCADCmd по корпусу - результаты
как у стока.
