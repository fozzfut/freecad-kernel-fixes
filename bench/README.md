# Набор действий владельца (bench)

Замер восьми действий владельца во FreeCAD на копиях его файлов. По этому набору судится каждый патч
ускорения (цель — 10× и больше, спек `docs/superpowers/specs/2026-09-21-mesh-pick-performance-design.md`, §11).
Замер ничего не упрощает в модели: те же файлы, те же настройки владельца (в том числе 6,4° у VR6).

FreeCAD запускается оффскрин (`QT_QPA_PLATFORM=offscreen`), без окна и без ввода мыши/клавиатуры: кадры рисует
`SoOffscreenRenderer` из собственного графа сцены вида, наведение идёт через `SoHandleEventAction` внутри процесса.

## Команды

Один прогон (из `bench/`):

    ./run_bench.sh <tag> <variant> <fc|hd> <FC_DIR> <файл|fixture:имя> <label> <действия,через,запятую>

- `tag` — имя папки `runs/<tag>` (она удаляется и создаётся заново);
- `variant` — имя варианта FreeCAD для отчёта (`stock`, `p012`, ...);
- профиль `fc` — чистый FreeCAD без дополнений; `hd` — плюс HybridDesign из установленного репозитория, только
  чтение, через ключ `-M`;
- `FC_DIR` — корень FreeCAD, например `"C:/Program Files/FreeCAD 1.1"`;
- файл — копия из `bench/files/` или тестовый документ `fixture:pad` / `fixture:holes1024` (см. «Тестовые документы»).

Тяжёлую деталь наведения прогон выбирает сам (см. ниже); `BENCH_HEAVY` не читается, а прогон, которому её
передали, пишет об этом в `notes`.

Переменные окружения: `BENCH_CUT_BASE` (тело для `edit_cut`, см. ниже), `BENCH_FILLET_REPS` (сколько правок в
`fillet_holes`, по умолчанию 4), `BENCH_BODY_OBJ` (объект для `edit_body`, по
умолчанию `Pad`), `BENCH_W`/`BENCH_H` (кадр, 1920×1080), `BENCH_TO` (таймаут прогона, с: по умолчанию 600 и не больше 600 — потолок владельца для одного запуска
FreeCAD, записан в `C:/dev/tools/fcslot.sh` 22.09.2026; значение больше урезается до 600), `BENCH_REFINE_TO` (сколько
`open` в профиле hd ждёт доводки сетки HybridDesign, с, по умолчанию 300), `BENCH_MIN_FREE_MB` (FreeCAD стартует,
только когда свободно столько МБ памяти, по умолчанию 4096 — правило машины для прогонов больше 1 ГБ; проверка
идёт уже внутри слота, прямо перед запуском, `tools/ramgate.sh`; для заведомо малого `fixture:pad` можно 0).

`run_bench.sh` печатает `exit=<код> tag=<tag> result=yes|NO errors=<имена ошибок из result.json через запятую или ->`.
Прогон с `errors` не `-` не зачётный: его разбирают и повторяют. `exit=0` — драйвер дошёл до конца и записал
`result.json` (процесс завершается сразу через `TerminateProcess`: при `os._exit` с HD процесс падал уже после
записи и отдавал 127); `124` — таймаут; `75` — за 30 мин так и не набралось свободной памяти; `2` — неверные
аргументы; `3` — не сделана копия настроек. Ошибки отдельных действий — в `errors` внутри `result.json`. По ходу
прогона драйвер пишет `progress.log` (секунды от старта драйвера и начатое действие) и `result.partial.json`:
прогон, убитый таймаутом, всё равно показывает, докуда дошёл.

Пример — дымовой прогон:

    ./run_bench.sh smoke-fc stock fc "C:/Program Files/FreeCAD 1.1" fixture:pad pad open,orbit,hover,select,edit_body,save

Серия базы — `run_matrix.sh <variant> <FC_DIR> <повторы>` (появится в Task 4). Свод «было → стало»:

    python report.py runs <base_variant> <variant> [reports/<имя>.md]

Тесты сводки (без FreeCAD): `python -m unittest discover -s tests -v`.

## Действия и метрики

| Действие | `result.json` → `actions.<имя>` | Метрика |
|---|---|---|
| Открыть файл в GUI | `open` | `open_s` — `openDocument`; `idle_s` — до простоя цикла событий (у HD это первая, грубая картинка); `first_frame_ms`, `second_frame_ms`; `gl_init_ms` — создание GL-контекста оффскрин-рендера, отдельно. В профиле hd ещё: `hd_refine_s` — от вызова `openDocument` до момента, когда очередь доводки HD пуста (все показанные детали нарисованы с качеством из файла), ожидание не дольше `BENCH_REFINE_TO` (300 с), не дождались или HD оставил показанные детали грубыми — `null`; `hd_refine_wait_s` — часть этого времени после `idle_s`; `hd_workers` — сколько процессов-доводчиков (FreeCAD.exe) HD запустил; `hd_refine` — состояние, их pid, собственная отметка конца HD и отчёт HD по деталям |
| Вращение | `orbit` | медиана и p90 кадра облёта: `overview` (24 кадра) и `closeup` (24 кадра, зум ×6) |
| Наведение и предвыбор | `hover` | отклик предвыбора + кадр подсветки по сетке 16×9 изометрии: `all`; `heavy` — те же точки сетки, попавшие на тяжёлую деталь (см. ниже), и её `heavy_object`, `heavy_label`, `heavy_triangles` |
| Выделение | `select` | `addSelection` → выделено (дерево + 3D) → кадр, до 20 целей |
| Правка параметра в Body | `edit_body` | правка → пересчёт → цикл событий занят → кадр: `edit`; части — `recompute`, `idle`, `frame`. В профиле hd у всех правок ещё `hd_refine_after` — сколько HD после последней правки доводил сетку до качества из файла (вне `edit`) |
| Правка STEP-детали (Part::Cut в VR6) | `edit_cut` | то же; плюс `faces` тела и `cut_valid` |
| Скругление на детали с 1024 отверстиями | `fillet_holes` | то же; плюс `valid` |
| Сохранение | `save` | `save_s` и `bytes` |

Сводки (`summary`) — `median`, `p90`, `min`, `max`, `n` в мс. Кроме действий в `result.json` пишутся `env`
(версия FreeCAD, md5 DLL ядра и `Part.pyd`/`PartGui.pyd`, `hd_loaded`, `hd` — путь и коммит установленного HD,
`pid`, GL-строки — должна быть RTX 3050), `cpu_load_pct` (загрузка всей машины за прогон: машина общая),
`children_at_exit` (дочерние процессы, остановленные в конце) и `errors` (трассировки по действиям; упавшее
действие в `actions` не попадает; `hover_heavy`, `open_hd_refine`, `edit_cut_hd_refine` — метрика не получена).
Кроме того `children_at_exit.hd_cancelled` — документы, чью доводку пришлось остановить в конце прогона.

**Тяжёлая деталь (`heavy`).** Тяжёлая — деталь с наибольшим числом нарисованных треугольников среди деталей, на
которые попала сама сетка 16×9. Треугольники считает Coin (`SoGetPrimitiveCountAction`) по корню вида детали: только
показанный режим отображения, у HD — та сетка, что сейчас нарисована. `heavy` — отклик в точках сетки на этой
детали; `hit_parts` — все задетые сеткой детали с числом точек и треугольников. Сетка сначала замеряется целиком,
как курсор идёт по только что открытой модели, а что лежит под каждой точкой, спрашивается потом (`getObjectInfo`,
вне замера). Заранее названная деталь не годится: винт ШВП VR6 (`Part__Feature014`) лежит в изометрии под
верхней плитой, и даже более густые сетки его не задевали (0 из 1536 точек в
`C:/dev/hybriddesign-render/phase1/out/hoverspike_vr6.json`). Сетка не задела ни одной детали — `heavy: null`,
`heavy_error` и ошибка `hover_heavy`: метрика не пропадает молча.

## Тестовые документы и база разреза

**`fixture:pad`** — Body с эскизом-прямоугольником и Pad 10 мм; строится в папке прогона при каждом прогоне.

**`fixture:holes1024`** — плита 200×200×10 с 32×32 = 1024 сквозными отверстиями Ø3 (`Part::Feature` `HolesPlate`,
скрыта, как её прячет команда PartDesign_Body) — BaseFeature тела `Body`, и `BenchFillet` (`PartDesign::Fillet`,
R 0,5 на верхней кромке одного отверстия). У верхней грани 1025 проводов — случай, где `BRepCheck_Face`
классифицирует провода попарно (спек, §8b). Фикстура проверяет себя: кромка найдена, скругление валидно, у верхней
грани 1025 проводов, показаны только `BenchFillet`/`Body`.

Строится **один раз**, заранее, и не внутри замера:

    sh tools/build_fixture.sh "C:/Program Files/FreeCAD 1.1"      # печатает exit=0 fixture=<путь> seconds=<с>

Файл — `files/fixture_holes1024-<md5 fixtures.py, 10 знаков>.FCStd` (рядом `.json` с md5 и версией FreeCAD):
правка кода фикстуры даёт новое имя, старый файл никогда не откроется по ошибке; сток и патч открывают один и тот
же файл, как и файлы владельца. Почему так (замерено 22.09.2026):
- в GUI каждый пересчёт плиты заново строит сетку верхней грани с 1025 проводами: 75–83 с на пересчёт в
  FreeCAD.exe против 4–5 с в FreeCADCmd (`runs/t3-gprobe/gprobe.json`, `runs/t3-probe/probe.json`); построенная
  внутри замера фикстура съела 287 с из 600 (первая попытка `runs/t3-holes`, прогон убит таймаутом);
- строится она в GUI (FreeCAD.exe оффскрин, `tools/build_fixture.sh`), не в FreeCADCmd: у файла из FreeCADCmd нет
  `GuiDocument.xml`, и в GUI все объекты открываются скрытыми — 0 треугольников и «правка» за 4 с, которая ничего
  не рисует (`runs/t3-vprobe/vprobe.json`). Без GUI `fixtures.build` такой файл строить отказывается;
- в GUI сборка шла 336 с при загрузке машины (`runs/build-holes1024/build.json`). Если файла нет, `build()` строит
  его и внутри прогона — такой прогон, скорее всего, не уложится в 600 с.

Прогон `open,fillet_holes` на ней (`runs/t3-holes/result.json`, 22.09.2026, загрузка машины 54 %): `open_s` 78,5 с
(пиковый рабочий набор 7,1 ГБ — сетка плиты), правка скругления медиана 83,3 с (76,0–84,2), `valid: true`, весь
прогон 419 с из 600. При сильной загрузке открытие и правка бывали в 2–3 раза дольше (открытие 247 с и правка 178 с
в `runs/t3-vprobe/vprobe.json`): тогда уменьшать `BENCH_FILLET_REPS`, не геометрию.

**База разреза для `edit_cut`** (`BENCH_CUT_BASE`) — самое тяжёлое по граням тело, кроме винта ШВП
`Part__Feature014` (его сетка при 6,4° — минуты, это действие «открыть»). Список тел с гранями —
`tools/list_bodies.py` (FreeCADCmd, файл в `BENCH_LIST_FILE`), выводы — `runs/t3-list/*.log`. В обоих файлах VR6 это
одно и то же тело, видимое в обоих:

BENCH_CUT_BASE для VR6 = Part__Feature013 (450 граней)
BENCH_CUT_BASE для VR6-current = Part__Feature013 (450 граней)

## Правила запуска

- Каждый FreeCAD — только через `C:/dev/tools/fcslot.sh` (так делает `run_bench.sh`), не больше одного прогона
  от одного исполнителя одновременно.
- **Профиль hd — два слота.** На тяжёлом файле HD рисует дорогие детали грубо и доводит их до качества из файла
  во втором FreeCAD.exe, который запускает сам (`hybriddesign/gui/mesh_process.py`, оффскрин, мимо fcslot).
  Поэтому `run_bench.sh` для hd занимает два слота из пяти: внешний `fcslot.sh` держит один, внутренний берёт
  второй и запускает FreeCAD. Драйвер в конце просит HD остановить доводку и завершает оставшиеся дочерние
  FreeCAD (`children_at_exit`); если FreeCAD убит таймаутом, `run_bench.sh` сам останавливает дочерние FreeCAD.exe
  его процесса, запущенные за время прогона (`leftovers.log`).
- **Доводка HD входит в открытие.** `wait_idle` возвращается на грубой картинке: доводчик опрашивается раз в
  60 мс, и цикл событий между опросами пуст. Поэтому `open` в профиле hd ждёт, пока HD не закончит проход
  (очередь доводки пуста: нет идущего прохода, нет сетки, ждущей вставки, и нет показанной детали, которую HD ещё
  довёл бы), пишет это время в `hd_refine_s`, и все следующие действия идут по сетке с качеством из файла, как в
  профиле fc. Не дождались за `BENCH_REFINE_TO` — `hd_refine_s: null` и ошибка `open_hd_refine` со списком
  недоведённых деталей. Очередь пуста, а показанные детали остались грубыми (HD исчерпал свои попытки,
  `hd_refine.state = stuck`) — тоже `null` и та же ошибка: картинка не та, что просит файл. Так было в ночном
  прогоне первой попытки правки: сторож машины `C:/dev/tools/fc-guard.ps1` приостановил оба доводчика HD как
  лишние FreeCAD, HD отказался от них через 90 с, и все 13 опущенных деталей VR6 остались грубыми; с 22.09.2026
  06:32 сторож доводчики (`hd-display-mesh-*`) не трогает. Кэш сеток HD лежит в `userdata` прогона, то есть каждый прогон — первое открытие, без кэша.
- **Доводка HD после правки.** После правки HD может нарисовать изменённую деталь грубо и отдать её доводчику:
  кадр в `edit` — первая картинка HD, как её видит владелец, а доводчик работает дальше. После последней правки
  драйвер ждёт, пока очередь доводки опустеет (вне замера `edit`), и пишет это в `hd_refine_after`; не дождались
  или детали остались грубыми — ошибка `<действие>_hd_refine_after`. Следующие действия идут по сетке с качеством
  из файла.
- **Вписывание вида — как «Вписать всё» FreeCAD.** Изометрия (`fit_iso`) и центр облёта считаются по габариту
  без узлов `SoSkipBoundingGroup`, как делает `View3DInventorViewer::viewAll` во FreeCAD 1.1.1. Сетка разметки HD
  (`HD_LayoutGrid`) — такой узел и подстраивает свой размер под видимый объём; с простым габаритом вид в профиле
  hd с каждым кадром отъезжал, и на `fixture:pad` сетка наведения попадала в деталь в 2 точках из 144 против 34 в
  fc. Отсечение (`autoclip`) по-прежнему по полному габариту: так ставит плоскости и сам FreeCAD.
- Наведение идёт в граф сцены Coin напрямую (`SoHandleEventAction`), мимо Qt-фильтра наведения HD
  (`hybriddesign/gui/hover_gate.py`, фильтр событий на `graphicsView`): строки hover профиля hd меряют тот же путь
  Coin, что и fc.
- Настройки владельца копируются заново на каждый прогон (`tools/cfg_sandbox.py`): живой `user.cfg` только
  читается. Если копии нет, `run_bench.sh` не запускает FreeCAD (`exit=3`): на настройках по умолчанию замер
  был бы не про файлы владельца.
- HybridDesign подключается ключом `-M` прямо из установленного репозитория, без ссылок (проверено: `smoke-hd`,
  `hd_loaded: true`). Байткод в него не пишется: `run_bench.sh` кладёт в `userdata/Mod/BenchNoPyc/Init.py`
  `sys.dont_write_bytecode = True` (переменные `PYTHON*` Python во FreeCAD игнорирует).
- **Junction.** Если когда-нибудь HD придётся подключать ссылкой `userdata/Mod/HybridDesign` (junction на
  репозиторий), ссылку надо снимать до `rm -rf "$RUN"` (`cmd //c rmdir <ссылка>`), иначе `rm -rf` сотрёт сам
  репозиторий HD.

## Оговорки оффскрина (измерено)

- Первый GL-контекст процесса создаётся ~1,5 с (загрузка драйвера). Это контекст замера, а не вида FreeCAD,
  поэтому он создаётся до первого кадра и пишется отдельно в `gl_init_ms`; в `first_frame_ms` его нет.
- Оффскрин-рендер ставит графу вида свою область W×H, и в ней же работают `getObjectInfo` и наведение; сетка
  наведения и выделения строится по этой области.
- В правке не считается окно тишины 200 мс, которым `wait_idle` убеждается, что цикл событий закончил: это
  ожидание замера. В `idle` правки маленькой детали входит таймер FreeCAD `activityTimer` (обновление состояния
  команд через ~150 мс после изменения, 7–10 мс работы); иногда — и обработка предупреждений
  `No valid GL context found!` в журнале через ~370 мс (13–16 мс работы), которых в окне не бывает.
- Миниатюра при сохранении оффскрин не рисуется (`imageFromFramebuffer failed`), а у владельца
  `SaveThumbnail=1`: в `save_s` нет рендера миниатюры 256×256.
